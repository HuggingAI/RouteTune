# RouteTune 一页产品定义

> 状态：产品与架构基线
> 日期：2026-10-10

## 一句话

RouteTune 用企业自己的请求、模型实测结果和人工反馈训练分类路由器，把每条请求交给“刚好够用”的模型，并通过受控发布让路由持续变好。

## 用户面对的不是模块，而是一条闭环

```text
接入候选模型
→ 导入真实请求
→ 建立路由基线并运行实验
→ 审阅失败与低置信度样本
→ 修正标注并训练候选版本
→ 对比新旧版本
→ 发布到统一 API
→ 线上 Trace 与反馈回流下一轮实验
```

模型池、安全、Trace、评测和标注不是五个独立产品。它们分别为候选执行、数据保护、结果复现、发布判断和持续学习服务。

管理台只有两个主要工作面：

- `API 运行`：运行大盘、请求记录、Playground 和统一 API 接入，回答生产流量现在运行得怎么样。
- `路由优化`：数据批次、批次审阅、Router 训练和版本发布，回答下一版 Router 怎样变得更好。

批次是审阅的工作单元，单条请求/模型输出是标注单元。线上 Trace 用于运行排查和反馈回流，不与正式批次审阅混成一张逐条列表。

## 核心特色

> 每个生产路由版本都来自真实业务数据和候选模型实测，经过评测后才由人工发布；所有线上决策都可以追溯到当时的不可变版本。

这项特色同时约束产品与工程：后台修改永远不能直接改变生产 API。

## 核心技术与产品分离

RouteTune Engine 是不依赖 Web、数据库和 Provider 的非生成式分类路由器。它接收请求特征和不可变策略包，输出固定路由标签、置信度、拒识结果和解释。

产品将其直接定义为概率分类 Router：输入请求文本，输出固定路由标签的概率分布，并通过置信度、OOD 和 fallback 规则形成最终决策。Router 家族与具体训练器分离：MVP 提供 `Auto` 和 `TF-IDF + Logistic Regression`，FastText、BERT/MiniLM 可作为后续本地训练器。Jev 只是一种可接入的外部概率分类器实现，不作为新的产品概念。

RouteTune Product 是路由控制平面：负责数据、实验、审阅、评测、版本、发布、安全、Trace 和统一 API。

执行层支持逐步扩展的三种粒度：

1. Request routing：整条请求选择外部或内部模型，MVP 主路径。
2. Cascade routing：失败、低置信度或质量不足时升级模型。
3. Token runtime：未来把 TokenRouter、SGLang 等本地协同推理引擎作为一种执行池接入，而不是在控制平面重造推理引擎。

## 产品主对象

- `Dataset Batch`：一组待运行或待比较的真实请求。
- `Experiment`：冻结数据、候选模型和评测规则的一次运行。
- `Review`：对确定输出的 pass/fail、原因、评分和修正。
- `Router Bundle`：训练得到的分类器制品。
- `Release`：Router Bundle、标签映射、模型池和安全策略的不可变快照。
- `Deployment`：环境到一个活动 Release 的可变指针；MVP 只有 `production`。
- `Trace`：一次调用与 Deployment、Release、路由决策和实际模型的完整关联。

## 发布规则

```text
草稿配置 / 新数据 / 新标注
          ↓
       候选版本
          ↓ 评测通过 + 人工发布
  Production Deployment
          ↓
 /v1/chat/completions 生效
```

- 修改模型池、标签映射、安全策略或训练数据，只影响草稿。
- Release 创建后不可修改，也不包含密钥明文。
- 统一 API 只读取 `production.active_release_id`。
- 发布和回滚都是活动指针切换。
- 每条 Trace 固定记录 `deployment_id`、`release_id` 和实际模型。

## MVP 成功标准

用户能够独立完成一个完整周期：导入请求、比较模型、审阅输出、训练候选路由器、查看评测结果、发布、通过统一 API 调用、从 Trace 标注失败样本并发布下一版。

不能进入这条闭环、不能帮助路由变得更好的能力，不进入 MVP。
