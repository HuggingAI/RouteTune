# 公开基准与 API 执行协议

## 目标

这条流水线只回答一个问题：当不同价位模型面对不同类型请求时，能否用非生成式分类器提前识别“便宜模型已经够用”的请求，并在明确质量线内降低平均成本。

公开基准只作为零客户阶段的工程 smoke，不是产品市场验证，也不能代替真实业务标注。当前 smoke 完成后不再扩充样本规模。

## 默认数据集

- 数据集：MMLU-Pro；
- 任务：英文多领域选择题；
- 规模：测试集 12,032 题；
- 许可：MIT；
- revision：`b189ec765aa7ed75c8acfea42df31fdae71f97be`；
- 测试文件 SHA-256：`0e24a191921c2f453518a537a8b2117bd137e7714d4ef1565e9ba06c1ecb9ad8`。

下载器固定 revision 并校验文件哈希。项目不提交数据文件，只在本地按需下载。

C-Eval 可用于中文补充验证，但其数据许可为 CC BY-NC-SA 4.0，因此不作为默认商业产品资产，也不随 RouteTune 分发。

## 候选模型原则

候选集合必须满足：

- 至少两个固定模型 slug；
- 存在明确的相对成本等级（如小模型低于大模型）；
- 同一轮实验中不更换模型版本；
- 不使用 `openrouter/free` 这类随机选择上游模型的聚合路由；
- 为模型设置稳定且唯一的 `cost_rank`，`1` 最便宜，数字越大越贵；
- 模型、成本等级、Provider 和 Prompt 共同构成实验上下文。

供应商价格、订阅方式和速率限制都会变化，不能固化成 RouteTune 的核心逻辑。当前验证不计算美元金额：只要在质量门槛内将一部分请求从高成本等级下放到低成本等级，节省就必然存在；具体金额留到真实部署时根据客户合同计算。

## 安全与额度闸门

每次执行都必须设置：

- `max_items`：进入本轮的题目数；
- `max_requests`：最多产生多少次新的外部请求；
- `min_interval_seconds`：低限额供应商需要时限制调用频率。

执行器不估算账单。免费、PAYG 和年度订阅都用请求数与调用间隔控制实验规模；正式批次还应在供应商控制台设置额度。Trace 保留 token 用量，未来需要时可以在外部报告层按客户的真实合同换算，不能反向影响本轮质量验证。

API Key 只从环境变量或显式指定的本地 env 文件读取：

- 不写入 TOML；
- 不写入 Trace；
- 不打印；
- 不放入异常消息；
- 不提交仓库。

## Trace 与断点续跑

`traces.jsonl` 对每次调用保存：

- benchmark、revision、题目 ID、类别和来源；
- 完整公开输入 messages；
- 内部模型 ID、Provider、实际 API model 和配置指纹；
- Prompt 版本；
- 原始输出与解析答案；
- 标准答案和 pass/fail；
- token、延迟、成本等级和 Provider request id；
- 失败状态与脱敏错误。

缓存键为：

```text
item_id + model_id + model_fingerprint + prompt_version
```

相同实验重复执行直接复用成功结果；失败请求不进入成功缓存，可以在修复配置后重试。这里的输入是公开题目，因此保留原文。未来真实业务 Trace 默认先经过安全模块脱敏，并采用 `metadata_only`、`redacted` 或经批准的 `encrypted_full` 存储策略。

对于 MiniMax 当前模型，M3 可以关闭 thinking，M2.x 不能关闭。执行器支持按模型配置 `thinking`、`reasoning_split` 和 `max_tokens`，并把 reasoning 与最终回答分字段保存；自动判分只读取最终回答。429 会记录为失败，冷却后重跑即可复用此前成功结果。

候选调用始终单线程串行执行，当前没有并发执行路径。`min_interval_seconds` 控制相邻请求间隔；HTTP 429 Trace 只保存 HTTP 状态、供应商结构化错误码与 `Retry-After`，不保存可能含敏感信息的原始错误正文。

## 判分与训练记录

模型被要求只返回一个选项字母。解析器只接受单字母、括号单字母或明确的 `answer is X` 形式，不从长段解释中猜答案。无法可靠解析即为失败。

只有当同一道题拥有所有候选模型的成功调用结果时，才生成一个 `EvaluationRecord`。至少 10 个完整记录后才写出训练数据；正式实验建议 300～1000 个分层样本。

## 分阶段执行

1. 1 道题 × 1 个模型：验证连接、鉴权和响应格式；
2. 10～20 道题 × 2 个候选：验证 Trace、缓存、判分和训练入口；
3. 工程 smoke 到此结束，进入最小产品实现；
4. 未来只有在回归或研究确有需要时才扩大公开样本。
